**Проблема:** сейчас все 6 файлов используют обычный `<img>` с прямым src на оригинальный jpg в `public/assets/cases/<slug>/...`. Каждое фото — несколько мегабайт. На странице кейса 1 hero + 12 галерея = 13 фото × 3 МБ = ~40 МБ. Lighthouse будет в красной зоне, мобильный пользователь не дождётся.

**Решение для Astro 6:** использовать встроенный `<Image>` из `astro:assets`. Astro автоматически делает webp + responsive sizes + правильные `srcset`. Но `<Image>` работает с импортированными ассетами, а не с публичными путями. Нужен паттерн:

```astro
---
// На странице кейса:
import { Image } from "astro:assets";

// Astro 6 поддерживает динамический импорт через import.meta.glob:
const photoModules = import.meta.glob<{ default: ImageMetadata }>(
  "/src/assets/cases/**/*.{jpg,jpeg,png,webp}",
  { eager: true }
);
---
```

**Это требует переноса фото из `assets/cases/` (вне src/) в `src/assets/cases/`** — иначе Astro не сможет их обработать через import.meta.glob.

**Решения по времени/сложности:**

**Вариант A (быстрый, рекомендуемый для Phase 5):**
1. **Не используем `<Image>`** — оставляем `<img>` с публичным путём.
2. **Конвертируем все используемые фото в webp вручную** через `sharp-cli` или `cwebp` командой:
   ```bash
   cd /Users/mariiavostrikova/claude/krylya/public/assets/cases
   # Для каждого .jpg, упомянутого в src/content/cases/*.md (cover + photos), создаём webp
   # Качество 80, max-width 1600px
   for case in aero-otkrytie dom-festival vklyuchi-partnerskij-vecher rasscvet-ng-korporativ 60-zhemchuzhin-schastya; do
     for jpg in "$case"/*.jpg "$case"/*.JPG "$case"/*.jpeg; do
       [ -f "$jpg" ] || continue
       npx sharp-cli "$jpg" -o "${jpg%.*}.webp" --format webp --quality 80 resize 1600
     done
   done
   ```
3. В шаблонах `<img src>` поменять расширение на `.webp` И добавить fallback через `<picture>`:
   ```astro
   <picture>
     <source srcset={`/assets/cases/${slug}/${cover.replace(/\\.(jpg|jpeg|png)$/i, '.webp')}`} type="image/webp" />
     <img src={`/assets/cases/${slug}/${cover}`} alt={...} loading="lazy" />
   </picture>
   ```

**Вариант B (правильный, дольше):** перенос всех фото в `src/assets/cases/`, переписывание всех 5 frontmatter `cover` и `photos` под import.meta.glob, использование `<Image>`. Минус: каждый раз когда Маша добавляет новое фото — нужна сборка. Плюс: автоматический responsive + webp.

**Решение для этого плана:** делаем **Вариант A** — конвертация в webp + `<picture>` для fallback. Это даёт основной выигрыш (webp на 30-40% меньше jpg), не требует реструктуризации, не меняет workflow Маши.

**Шаги:**

1. **Установить sharp-cli как devDependency:**
   ```bash
   cd /Users/mariiavostrikova/claude/krylya && npm install -D sharp-cli
   ```

2. **Создать скрипт `scripts/optimize-case-photos.mjs`:**
   ```js
   #!/usr/bin/env node
   import { readdirSync, statSync, existsSync } from "node:fs";
   import { join, extname, basename } from "node:path";
   import { execSync } from "node:child_process";

   const ROOT = "/Users/mariiavostrikova/claude/krylya/public/assets/cases";
   const CASES = ["aero-otkrytie", "dom-festival", "vklyuchi-partnerskij-vecher", "rasscvet-ng-korporativ", "60-zhemchuzhin-schastya"];

   for (const c of CASES) {
     const dir = join(ROOT, c);
     if (!existsSync(dir)) continue;
     const files = readdirSync(dir).filter(f => /\.(jpe?g|png)$/i.test(f));
     for (const f of files) {
       const src = join(dir, f);
       const webp = join(dir, basename(f, extname(f)) + ".webp");
       if (existsSync(webp)) continue;
       try {
         execSync(`npx sharp-cli "${src}" -o "${webp}" --format webp --quality 80 resize 1600`, { stdio: "inherit" });
       } catch (e) {
         console.error(`Failed: ${f}`, e.message);
       }
     }
   }
   ```
