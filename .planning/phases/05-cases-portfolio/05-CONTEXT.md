<decisions>
## Implementation Decisions

### Структура страницы кейса
- **D-01 (Hero):** Большое фото-обложка на всю ширину с заголовком кейса поверх. Кинематографичный hero — фото сразу задаёт настроение мероприятия. Это новый компонент (у нас такого паттерна ещё нет).
- **D-02 (Факты):** Ключевые факты проекта (формат, гости, длительность, площадка, дата) — чипами под H1 в hero. Паттерн чипов уже есть на главной (Hero) и в LocalExpertise — переиспользуем.
- **D-03 (Тон текста):** Структура «Задача → Решение → Итог» (стандарт B2B-кейсов). Читается легко, SEO-ориентировано.
- **D-04 (Конец страницы):** Кнопка «Обсудить мероприятие» (CTA на форму) + карточка следующего кейса (стрелка дальше). Двойной путь — конверсия + удержание внимания.

### Фото внутри кейса
- **D-05 (Раскладка):** Сетка из 3 колонок одинакового размера. Простой паттерн, быстро в реализации, работает с любыми пропорциями фото.
- **D-06 (Объём):** Топ-12 фото на каждом кейсе. Маша отбирает вручную самые сильные кадры. Качество > количество, страница не утомляет, быстро грузится.
- **D-07 (Поведение клика):** Ничего не происходит — фото в фиксированном размере в сетке. Без лайтбокса, без открытия в новой вкладке. Если пользователь хочет крупнее — есть hero на странице кейса.
- **D-08 (Обложка):** Маша указывает обложку вручную в frontmatter каждого кейса (поле `cover` со ссылкой на конкретный файл). Маша знает лучше, какое фото передаёт настроение.

### Витрина /cases/
- **D-09 (Layout):** Карточки одинаковой сетки. Паттерн уже есть в `src/components/blocks/CasesPreview.astro` и на витрине `/services/` — переиспользуем для единообразия.
- **D-10 (Группировка):** Без группировки, сортировка по дате (свежие сверху). При 5 кейсах группы выглядят пустыми.
- **D-11 (Карточка):** Фото-обложка + название проекта + клиент (или «частное мероприятие» для анонимных) + один яркий чип факта (например «300+ гостей»). Минимум текста, максимум визуала.
- **D-12 (Релиз):** Все 5 кейсов публикуются одновременно после написания всех текстов. Один цельный визуальный релиз.

### Фотоальбом (PAGE-14b)
- **D-13 (Скоуп):** В Phase 5 не делаем. Откладываем на отдельную фазу, когда соберётся больше архива или появится ясная роль альбома.

### Анонимная подача юбилея
- **D-14:** Кейс «60-летний юбилей в кругу близких» подаётся без имени. На витрине — клиент: «частное мероприятие». В тексте — формат, число гостей, площадка, концепция, без личных деталей. Пример формулировки: «Юбилей красивой женщины в семейном кругу — 60 лет».

### Лица крупным планом
- **D-15:** На фотографиях используем только общие кадры — без крупных портретов гостей. При необходимости размываем лица. Применяется ко всем 5 кейсам.

### Claude's Discretion
- **Технические детали реализации:** работа с изображениями (sharp / @astrojs/image для оптимизации), lazy loading, форматы (webp), responsive sizes — выбираю подходящий стандарт для Astro 6.
- **Точные пропорции карточек, размеры hero-обложки, отступы:** придерживаюсь дизайн-системы Phase 2.
- **Ссылки между кейсами и услугами:** на странице каждого кейса добавляю ссылку на релевантную услугу (через service reference в Content Collections). На страницах услуг — добавляю ссылку на 1-2 релевантных кейса (закрывает отложенный пункт из Phase 4).

</decisions>

## Existing Code Insights

### Reusable Assets
- **CasesPreview.astro** — карточка кейса для главной с такой же логикой `getCollection("cases").sort(by date).slice(0, 3)`. Витрина `/cases/` повторяет логику без `.slice()`.
- **Hero.astro** (главная) — паттерн «бровка + H1 + чипы фактов». Переиспользуется на странице кейса (но с большим фото вместо белого фона).
- **JsonLdService.astro** — структура JSON-LD компонента-обёртки. Для кейса делаем аналогичный JsonLdEvent.astro.
- **Breadcrumbs.astro** — готовый компонент, передаётся `crumbs[]`.
- **PricingTeaser, ContactBlock** — стандартные блоки в конце страниц услуг. На странице кейса используем ContactBlock в конце.
- **`<article class="prose-content">`** — паттерн обёртки для рендера Markdown-контента кейса (используется на страницах услуг).
- **Content Collection schema** (cases) — есть в `src/content.config.ts`. Поля frontmatter: title, slug, client, date, segment, challenge, solution, results, photos, featured. **Изменение:** добавить поле `cover` (string) для ручного указания обложки. Удалить (или сделать optional) поле `testimonial` — отзывы не публикуем в v1.

### Established Patterns
- **Stat chip:** `<span class="bg-yellow text-black px-2 py-1 text-sm">…</span>` или с жёлтой точкой `<span class="inline-block h-1.5 w-1.5 bg-yellow rounded-full"></span>` — для фактов в hero и витрине.
- **Card:** `<a class="group block bg-white border border-gray-light p-8 hover:border-yellow hover:shadow-lg transition-all">` — паттерн карточки на витрине из CasesPreview.
- **Section + Container:** все блоки оборачиваются в `<Section>` + `<Container>` для консистентного outer spacing.
- **SEO + Breadcrumbs наверху** — паттерн всех страниц: hero внутри `<BaseLayout>`, в `slot="seo"` идут Seo + JsonLd компоненты.

### Integration Points
- **Главная (`CasesPreview`):** уже ссылается на `/cases/<slug>/`. После создания шаблона ссылки заработают для 5 кейсов автоматически.
- **Страницы услуг:** добавить блок «Похожие кейсы» с 1-2 карточками после основного текста (закрывает отложенный пункт Phase 4 «ссылка на ≥1 кейс»). Через `getCollection("cases")` с фильтром по `service` reference.
- **Footer / Header navigation:** «Кейсы» уже в меню (видно в Hero), ссылка ведёт на `/cases/`. Шаблон работает сразу.

<specifics>
## Specific Ideas

- **Анонимный кейс «60 жемчужин счастья»:** название стилизовано в духе ювелирной эстетики (60 жемчужин = 60 лет). Подача: «юбилей красивой женщины в семейном кругу». В frontmatter: `client: "Частное мероприятие"`. На витрине чип факта может быть «60 гостей» или «8 часов программы».
- **«ССК» как клиент:** в кейсе ВКЛЮЧИ-партнёрский вечер указываем как «ЖК ВКЛЮЧИ / девелопер ССК» или просто «ЖК ВКЛЮЧИ» (Маша знает точное согласованное имя).
- **Иконка / визуальный акцент чипа:** жёлтая точка (как в LocalExpertise) или жёлтая полоска-маркер — выбрать на этапе планирования, отдать предпочтение тому, что уже использовалось.
- **Hero overlay:** на большом фото-обложке нужен лёгкий градиент снизу-вверх, чтобы белый текст H1 был читаем на любых фото. Чёрный градиент с прозрачностью 60% — стандарт. Вариант: окно с заголовком на чёрном плашке поверх правого нижнего угла фото.

</specifics>

<deferred>
## Deferred Ideas

### Отложено на отдельную фазу
- **Фотоальбом (PAGE-14b)** — отдельная страница `/album/` или блок в /cases/ с подборкой фото с разных мероприятий, не привязанных к кейсу. Делается, когда соберётся больше архива или появится ясная роль (например, для контента в SMM).

### Отложено до накопления материала
- **Цитаты-отзывы клиентов** — формально остаётся в схеме Content Collections (CONT-03), но не выводим в v1. Когда соберётся ≥3 сильных текстовых отзыва — отдельная фаза «социальные доказательства» с возвратом блока на страницы услуг и кейсов.
- **Логотипы клиентов** — пока не публикуем. Если в будущем появится 6-8+ узнаваемых логотипов с согласием — можно вернуть блок «Ключевые клиенты» на главную.
- **Бюджеты на кейсах** — клиенты против указания сумм, политика «не показываем».

### Out of scope для v1
- Фильтры/поиск по кейсам — функция без смысла на 5 кейсах.
- Лайтбокс для фото — Маша выбрала простую сетку без увеличения.
- Карта с маркерами площадок — интересная идея, но не нужна для v1.

</deferred>
